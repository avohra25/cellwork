# cellwork


A spreadsheet engine in Erlang/OTP: a formula language with real
spreadsheet semantics, an evaluator, incremental recalculation over a
dependency graph with cycle detection, a live `gen_server` that pushes
changes to subscribers, CSV import/export, and a command-line tool with a
REPL. No dependencies beyond OTP.

```
$ cellwork eval examples/budget.csv
  | A              | B       | C       | D
--+----------------+---------+---------+------
1 | Item           | Monthly | Yearly  | Share
2 | Rent           |    1850 |   22200 |  70.9
3 | Groceries      |     420 |    5040 |  16.1
4 | Transit        |      96 |    1152 |   3.7
5 | Internet       |      60 |     720 |   2.3
6 | Fun            |     185 |    2220 |   7.1
7 | Total          |    2611 |   31332 |   100
8 | Items over 500 |       1 | Average | 522.2
```

Needs OTP 26+ and rebar3.


## The formula language

- **References**: `B3`, `$A$1`, `AA10`, ranges `A1:C4` (in any corner
  order). Grid is `A`..`XFD` by 1..1048576.
- **Operators**, loosest to tightest: comparisons `= <> < <= > >=`, text
  join `&`, `+ -`, `* /`, `^`, unary minus, postfix `%`. As in Excel,
  `-2^2` is `4` and `2^3^2` is `64`.
- **Values**: IEEE doubles shown General-style (`0.1+0.2` shows `0.3`),
  text, `TRUE`/`FALSE`, blanks, and errors `#DIV/0!`, `#VALUE!`,
  `#REF!`, `#NAME?`, `#NUM!`, `#N/A`, `#CYCLE!` that propagate through
  formulas. Numeric-looking text coerces in arithmetic, a blank is zero
  or empty text, and comparisons order numbers < text < booleans with
  case-insensitive text. A leading `'` forces text.
- **Functions** (29): `SUM PRODUCT AVERAGE MIN MAX COUNT COUNTA COUNTIF
  SUMIF IF IFERROR ISERROR ISBLANK ISNUMBER ISTEXT AND OR NOT ABS INT SQRT
  POWER MOD ROUND CONCAT LEN UPPER LOWER TRIM`. `IF` and `IFERROR` are
  lazy. Aggregates skip text and booleans read from cells but coerce
  arguments written directly. `COUNTIF`/`SUMIF` take criteria such as
  `">=10"`, `"<>done"` or `"ap*"` with `*`/`?` wildcards.

The lexer and parser are generated by `leex` and `yecc`. A
pretty-printer emits minimal parentheses and is checked to round-trip
through the parser on thousands of random formulas.

## How recalculation works

`cell_sheet` is a purely functional sheet. For every formula cell it
keeps the sorted list of cells it reads, plus a reverse index from each
cell to the formulas that read it. Editing a cell:

1. parses the new inputs (a batch is atomic: one bad formula and nothing
   changes),
2. updates both indexes for the edited cells only,
3. collects the edited cells and everything that transitively depends on
   them,
4. orders that set with Tarjan's strongly connected components algorithm,
   which also finds cycles: every cell in a circular group becomes
   `#CYCLE!`, and cells downstream see the error,
5. re-evaluates in that order and returns exactly the cells whose value
   changed.

Breaking a cycle later recovers every cell in it. Copying a cell shifts
its relative references the way paste does (`$` parts stay put, and
references pushed off the grid become `#REF!`).

```erlang
{ok, S1, _} = cell_sheet:set_many(cell_sheet:new(),
                                  [{"A1", "10"}, {"A2", "=A1*2"}, {"A3", "=SUM(A1:A2)"}]),
{ok, S2, Changed} = cell_sheet:set(S1, "A1", "5"),
%% Changed = [{{1,1},5.0}, {{1,2},10.0}, {{1,3},15.0}]
<<"15">> = cell_sheet:display(S2, "A3").
```

The tests check this with randomized differential testing: after
hundreds of random edit sequences, the incrementally maintained sheet
must match a sheet built fresh from the final inputs, a full
recalculation, and (for acyclic sheets) a naive recursive evaluator, and
the reported changes must be exactly the cells that differ.

## Live sheets

`cell_server` wraps a sheet in a `gen_server`. Writers are serialized,
and subscribers receive one message per successful edit or batch:

```erlang
{ok, S} = cell_server:start_link(),
ok = cell_server:subscribe(S),
{ok, _} = cell_server:set(S, "B1", "=A1*3"),
{ok, _} = cell_server:set(S, "A1", "2"),
receive {cellwork, S, Changes} -> Changes end.
%% first message: [{{2,1},0.0}], then [{{1,1},2.0},{{2,1},6.0}]
```

Subscribers are monitored and dropped when they exit.

## CSV and the CLI

`cell_csv` reads and writes RFC 4180 CSV (quoted fields, embedded commas,
quotes and newlines, CRLF or LF). Each field is a cell input, so formulas
work, and `export_inputs/1` writes a file that loads back identically.

```
cellwork eval FILE.csv [--csv]   evaluate and print the grid (or CSV of values)
cellwork get FILE.csv REF        print one cell's value
cellwork check FILE.csv          list cells holding errors, exit 1 if any
cellwork repl [FILE.csv]         interactive editing
```

```
$ cellwork repl
> A1 10
A1 = 10
> B1 =A1*2
B1 = 20
> A1 7
A1 = 7
B1 = 14
> :deps A1
reads:
read by: B1
> :save out.csv
saved out.csv
```

REPL commands: `REF value`, `REF =formula`, `REF` alone to clear,
`:show`, `:get REF`, `:deps REF`, `:save FILE`, `:help`, `:quit`.

## Layout

| Module | Role |
| --- | --- |
| `cell_ref` | A1 reference parsing and printing |
| `cell_lexer.xrl`, `cell_parser.yrl` | tokenizer and LALR grammar |
| `cell_formula` | AST, printer, dependency extraction, reference shifting |
| `cell_value` | value types, coercion, comparison, number formatting |
| `cell_eval` | expression evaluator and built-in functions |
| `cell_sheet` | dependency graph, incremental recalculation, cycles |
| `cell_server` | live sheet process with subscriptions |
| `cell_csv` | CSV parsing, encoding, loading and export |
| `cellwork` | escript CLI and REPL |
